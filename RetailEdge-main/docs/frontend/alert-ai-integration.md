# RetailEdge AI / Module Handoff & Realtime Events

This guide documents how operational events generated by AI vision pipelines, IoT edge nodes, and module analytics are aggregated into centralized alerts, as well as the Socket.IO realtime event contracts.

---

## 2. Realtime Socket.IO Event Contracts

The frontend uses Socket.IO client architecture to listen for real-time lifecycle events:

### `alert.created`
- **Payload**: Full `Alert` object.
- **Frontend Action**:
  - Prepends alert to `alerts` state.
  - Increments `total` and relevant severity KPI count (`critical`, `warning`, or `info`).
  - Increments unread badge count in sidebar and header.

### `alert.updated`
- **Payload**: `{ alertId: string, updates: Partial<Alert> }`
- **Frontend Action**: Updates matching alert in the list and details view if active.

### `alert.acknowledged`
- **Payload**: `{ alertId: string, acknowledgedAt: string, acknowledgedBy: string }`
- **Frontend Action**:
  - Updates alert status to `ACKNOWLEDGED`.
  - Shifts count in Alert Status card (decrements Open, increments In Progress).

### `alert.resolved`
- **Payload**: `{ alertId: string, resolvedAt: string, resolvedBy: string }`
- **Frontend Action**:
  - Updates alert status to `RESOLVED`.
  - Increments `resolved` KPI counter.
  - Updates Alert Status progress bars.

### `alert.assigned`
- **Payload**: `{ alertId: string, assignedTo: string }`
- **Frontend Action**: Updates `assignedTo` attribute and appends history timeline entry.
